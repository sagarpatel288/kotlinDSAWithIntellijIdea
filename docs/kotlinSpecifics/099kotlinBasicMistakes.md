## Lessons learned through experience

* It is one thing to understand the concept, and remembering it is another thing. 
* Remembering a concept is one thing, and hand-writing it (implementation) is another thing.
* When we implement (whiteboard and handwritten), we need to take care of several things, such as:
* Public vs. private - class, properties, and members
* Nullable vs. non-nullable properties
* Global properties vs. local properties
* Mutable vs. immutable properties
* Tracking, updating, and maintaining properties
* Computational property vs. a function
* Which functions will be the part of the data class?
* For a function:
  * What will be the parameters? Which parameters? How many?
  * Nullable vs. non-null parameters with rationale (reasoning).
  * What will be the return type?
  * Nullable vs. non-null return type.
  * Recursion vs. iteration
  * Base conditions
  * Edge cases
  * Conditions
  * Conditional statements
  * Pass by reference vs. pass by value
  * Deep copy vs. shallow copy
* Null safety
  * Null safe operator
  * Elvis operator
  * Scope functions
  * requireNotNull
  * checkNotNull
* Exception
  * Inbuilt exception vs. custom exception
* Language, framework, and idiomatic code
* And we need to justify the implementation.
* Also, writing the solution (implementation) on a whiteboard is one thing, and implementing it for a real project is another thing.
* When we write it for the real project, we need to take care of architecture, time, efforts, priorities, impact, resources, consequences, etc.
